eMudhra Intermediate CA Compromise

20th October 2026

The private keys of eight eMudhra intermediate CA certificates have been compromised. They chain to roots trusted by the Mozilla, Microsoft, Apple and Chrome root programs and by many downstream trust stores. An attacker with the private key of any of the compromised intermediate CAs could impersonate any website or service.

Root programs are run by operating system and browser vendors to vet certificate authorities and decide which ones their products trust. Trust stores are the lists of trusted root certificates that operating systems, browsers, language runtimes, libraries and applications use to verify certificates, and many are based on the root programs' lists.

This page is a summary of the English page, which is updated more often. See it for the latest and more detailed information.

What actions can users take?

Users should update their browsers and operating systems to the latest versions as soon as possible. The certificates have been blocked in Firefox and Chrome since the 17th of October, on Microsoft platforms since the 20th and on Apple products since the 22nd.

A ✅ only means that the connection failed. Browsers do not tell the page why, so a network problem looks the same as a rejected certificate. To double-check, open the link in that row: if it loads without a warning page, the browser is vulnerable.

On 22nd October 2026, two chains marked No CT were added. Their leaf certificates were never logged to Certificate Transparency (CT), so clients that enforce CT reject them even if they still trust the intermediate. A successful connection to these hosts means the client trusts the compromised intermediates and does not enforce CT. As described on the English page, these are the clients that can be attacked without anyone noticing.

These results apply only to the browser running this check. To check curl or other applications, see the English instructions.

For developers and administrators

Mozilla, Microsoft, Apple and Chrome have already remediated the compromise for their users through their tools for distributing revocation information. However, many other clients do not consume revocation information and require software updates to ensure they no longer trust the compromised intermediates. These include applications and libraries that ship their own CA bundle, and apps built on Electron, such as Slack and Discord. Electron apps only pick up Electron's fix once they are updated to a version built on a patched Electron release. Updating the operating system or browser may not be enough for these clients.
